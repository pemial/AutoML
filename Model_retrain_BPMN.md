## Триггер запуска переобучения модели
Система мониторинга фиксирует одно из событий: дрейф данных (PSI > 0.2), деградацию метрик в проде (Recall < 0.85), накопление порогового объёма новых размеченных записей (≥ 300 для датасета из 918 наблюдений) или плановую дату (ежеквартально).
## Получение и подготовку новых данных
Из ЕМК/DWH выгружаются 11 клинических признаков и фактический исход HeartDisease (0/1) за период с последнего обучениям
## Обучение новой версии модели
Очистка, дедупликация, импутация, One-Hot Encoding для категориальных, StandardScaler для числовых, проверка схемы, разделение на train/test, GridSearchCV с 5-fold кросс-валидацией на train
## Проверку качества модели
Оценка на тесте: Recall > 0.85 (основной критерий), Precision, Accuracy.
## Принятие решения о возможности публикации новой версии
Автоматическое одобрение при Recall > 0.85 и приемлемых Precision / Accuracy; ручное ревью при пограничных значениях
## Регистрация или сохранение новой версии модели
Сохранение артефактов в MLflow Model Registry: версия (semver), датасет, гиперпараметры, метрики, автор; статус Staging → Production.
## Деплой модели
Канареечный релиз (5% → 25% → 100%), мониторинг latency/ошибок, автоматический откат при инцидентах
## Действия при неуспешном прохождении проверок
При провале валидации данных, метрик или решения — уведомление команды, логирование причин, сохранение в реестре со статусом rejected, текущая прод-версия остаётся активной.
